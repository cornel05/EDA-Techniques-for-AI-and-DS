⚠️ Class Imbalance Findings

Potential issue requiring mitigation in model training

  • 3.03× Imbalance Ratio: Digit 1 dominates with 18,960 samples (19.1%) while digit 9 has only 6,254 (6.3%). A model trained naively will be biased toward predicting the majority class. For the upcoming ML assignment, use weighted cross-entropy loss (weight each class inversely proportional to its frequency) or oversampling of minority classes (digits 0, 8, 9) via techniques like random oversampling or SMOTE on feature embeddings.
  • Consistent Imbalance Across Splits: The class distribution pattern is stable across both the training set (73,257 images) and test set (26,032 images), confirming the split is stratified. This means evaluation metrics on the test set faithfully reflect the same skew seen during training — use macro-averaged F1 rather than accuracy to get an unbiased view of per-class performance.
  • Moderate Imbalance, Not Severe: At 3× ratio this is manageable — it does not require aggressive resampling. A weighted loss function alone is likely sufficient and avoids introducing artificial data.

🎨 Per-Class Pixel Statistics Insights

From Section 4.5 — mean brightness and RGB channel values per digit class

  • Brightness Is Uniform Across Classes (Δ ≈ 0.009): All ten digit classes fall within a brightness range of 0.4495 (digit 7) to 0.4586 (digit 0) — a spread of only ~0.009. This is negligibly small, meaning the model cannot exploit brightness as a discriminative feature. Per-class brightness normalization is therefore unnecessary.
  • Blue Channel Consistently Dominant: Across all digit classes, the B channel mean (≈0.470–0.477) is consistently higher than R (≈0.437–0.447) and G (≈0.442–0.452). This slight blue bias likely reflects outdoor urban scene backgrounds (sky, shadows) in SVHN street photographs. Channel-wise normalization using the computed per-channel means and stds is important to remove this systematic bias before training.
  • Digit 7 Is the Darkest; Digit 0 the Brightest: Digit 7 has the lowest brightness (0.4495) and lowest R, G, B channel means across all classes, while digit 0 is the brightest (0.4586). The difference is small but consistent. This could reflect how these digit shapes are rendered in house-number signage (e.g., digit 7 strokes cover less area). It does not indicate a quality problem, but is worth noting if diagnosing class-specific model errors later.
  • No Outlier Classes: Since pixel statistics are essentially identical across all 10 classes, any misclassification errors in the trained model are unlikely to stem from systematic lighting or colour differences — they will be due to shape ambiguity (e.g., 1 vs 7, 6 vs 9) or background noise, guiding where to focus error analysis.

✅ Dataset Consistency & Quality

Structural properties that simplify the preprocessing pipeline

  • Perfect Size Uniformity: All 99,289 images are exactly 32×32×3 RGB — no resizing, padding, or aspect-ratio correction is required. This greatly simplifies the DataLoader pipeline.
  • Zero Corrupted Images, 100% Label Coverage: No integrity issues were found. The only detected duplicate (1 exact pair in 99,289 images, 0.00%) is negligible and does not affect training.
  • Moderate Contrast (RMS std ≈ 0.20): The overall pixel standard deviation of ~0.20 indicates many images are low-to-medium contrast street scenes with cluttered backgrounds. The model will need to learn to suppress background noise — making data augmentation and potentially contrast normalization particularly valuable.

🛠️ Preprocessing Recommendations

Concrete steps to apply before model training in the ML assignment

  • Channel-wise Normalization (Required): Subtract per-channel means and divide by per-channel stds computed from the training set: mean=[0.4416, 0.4461, 0.4718]  std=[0.2040, 0.2081, 0.2058] This removes the blue-channel bias and centres each channel, which stabilises gradient flow during training.
  • Data Augmentation (Strongly Recommended): SVHN images contain heavy background clutter from real street scenes. Apply during training only: random crops with padding (e.g., pad 4px then crop back to 32×32), colour jitter (brightness ±20%, contrast ±20%), and slight rotations (±10°). Avoid horizontal flips — they would make digits like 6/9 and 2/5 ambiguous.
  • Weighted Loss or Oversampling for Imbalance: Use torch.nn.CrossEntropyLoss(weight=class_weights) where each weight = total_samples / (num_classes × class_count). This is simpler and more stable than oversampling for a 3× imbalance.
  • Evaluation Metric: Report macro-averaged F1-score alongside accuracy. Given the class imbalance, accuracy alone will overstate performance on minority classes (digits 0, 8, 9).
  • Architecture Compatibility: 32×32 input is optimal for lightweight CNN architectures (LeNet-5, compact ResNet-20, or MobileNetV2). No architectural adaptation is needed for input size.
